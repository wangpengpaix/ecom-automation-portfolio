把多平台发布能力，收进一个后台

自媒体矩阵内容中台：账号接进来 → 内容准备好 → 一键或定时发到多平台 → 看发布结果。以「三通道」架构应对各平台开放程度的差异，把发布这件事做成可调度、可观测、可降级的工程链路。

02发布通道

不要指望用一种方式打通所有平台——它们的开放程度完全不同。每个平台走最适合它的那条通道，失败时按既定边界降级，绝不静默失败。

通道 A · 官方 API

已实现
公众号（抖音 / 快手待资质）
AppID / Secret 与 OAuth 认证。公众号已实现完整链路：建账号探活 → 传素材 → 建内容 → 写草稿 → 发布。抖音 / 快手为骨架，需平台资质审批后填充，未接入前所有发布操作明确 fail-closed。
AppID / SecretOAuth草稿箱fail-closed

通道 B · Web 接口直连

已实现
B站
直接调用站点 Web 接口，以 Cookie（SESSDATA + bili_jct）认证，含分片上传参数处理。相比浏览器自动化更快、更省资源，代价是需跟随站点接口变动维护。
Cookie 认证分片上传轻量

通道 C · 浏览器自动化

骨架
小红书 · 视频号（公众号降级兜底）
基于 Playwright 复用人工导出的 storage_state 登录态，按页面结构驱动。铁律：不自动登录，登录态只能人工导出；平台改版只改 selectors YAML、不改代码。同一套引擎同时承担公众号在 48001 后的降级发布。

03功能模块

V1.0 范围聚焦「账号管理 + 多平台发布聚合」，养号互动模块按产品决策后置。

01 · 账号矩阵与健康度

已落地
多平台账号接入 · 登录态运维 · 矩阵看板
统一接入各平台账号并维护其登录态生命周期，输出跨账号的矩阵健康度——登录态有效期、连续失败次数、上次成功时间，让「哪个号快掉线」在出问题前就可见。
登录态健康度凭据不回传

02 · 内容生产管线

已闭环
选题池 → 生成 → 审核 → 入队
选题池产出选题，按风格档生成正文，经违禁词与格式校验后进入审核态、由人工放行，通过后自动入发布队列。平台格式适配（标题字数、公众号 HTML 与摘要长度、去重相似度）在生成阶段即校验，避免不合格内容流入队列；无模型时降级模板不阻塞。
选题池风格档人工审核降级不阻塞

03 · 素材库与封面

已落地
素材入库 · 封面处理 · 图片库权限
素材与封面统一入库管理，发布时按平台要求处理封面与配图；封面图片库权限按真实能力判定，避免因误判导致发布中断。
素材库封面权限判定

04 · 多平台发布调度

已落地
自旋引擎 · 错峰 · 水位线 · 重试
发布任务由轮询 worker 带退避地自推进（自旋引擎），避免固定间隔空转；调度侧保留错峰与访问水位线，避免多账号在同一时刻集中请求平台；失败按策略重试，步骤水位线记录每条任务走到哪一步。
自旋引擎错峰水位线重试

05 · 发布通道与降级

已打通
两级链路 · 条件降级 · fail-closed
同一发布动作优先走官方 API；遇到接口权限不足（48001）或出口 IP 不在白名单这两类典型失败时，自动降级到浏览器通道完成发布，而非直接中断。未接入真实发布的能力一律明确报错，不模拟成功。

06运行方式

单机单端口即可跑起来，无需中间件。

STEP 01

配置与建表

安装依赖，从示例配置生成环境变量文件，执行 Alembic 迁移建表。

STEP 02

起服务与 worker

启动 FastAPI 单端口服务并另起一个发布 worker，两者共享同一数据库。

STEP 03

接入账号

按平台选择通道：官方 API 填 AppID/Secret，Web 直连填 Cookie，浏览器通道人工扫码导出登录态。

STEP 04

生产与发布

选题 → 生成 → 审核入队 → 定时或手动发布，在概览与发布任务页查看进度与结果。
